# 📊 E-Commerce Revenue & Customer Retention Engine

An end-to-end commercial analytics platform examining 100,000+ Brazilian e-commerce transactions (Olist dataset). Leverages **DuckDB SQL**, columnar **Apache Parquet** storage, and **Streamlit** to evaluate customer cohort retention decay, segment revenue concentration via RFM scoring, and isolate supplier-side catalog vulnerability through Pareto distribution modeling.

## Analytical Deep Dives

### 1. Cohort Retention & Habitual Decay
To test whether customer acquisition establishes an ongoing retention flywheel, transactions were organized into an 18-month triangular retention matrix. Customers were grouped into monthly acquisition cohorts based on their initial transaction timestamp ($t_0$).

The retention rate $R(c, t)$ for cohort $c$ at elapsed month $t$ is formulated as:

$$R(c, t) = \frac{\text{Active Customers}_{c, t}}{\text{Cohort Size}_c} \times 100\%$$

```sql
-- Monthly Cohort Retention Matrix (DuckDB SQL)
WITH cohort_items AS (
    SELECT 
        c.customer_unique_id,
        MIN(DATE_TRUNC('month', o.order_purchase_timestamp)) OVER(PARTITION BY c.customer_unique_id) AS cohort_month,
        DATE_TRUNC('month', o.order_purchase_timestamp) AS order_month
    FROM fact_orders o
    JOIN dim_customers c ON o.customer_id = c.customer_id
    WHERE o.order_status = 'delivered'
),
cohort_index AS (
    SELECT 
        customer_unique_id,
        cohort_month,
        order_month,
        (EXTRACT(year FROM order_month) - EXTRACT(year FROM cohort_month)) * 12 +
        (EXTRACT(month FROM order_month) - EXTRACT(month FROM cohort_month)) AS period_number
    FROM cohort_items
)
SELECT 
    cohort_month,
    period_number,
    COUNT(DISTINCT customer_unique_id) AS active_customers,
    ROUND(COUNT(DISTINCT customer_unique_id)::FLOAT / 
          FIRST_VALUE(COUNT(DISTINCT customer_unique_id)) OVER(PARTITION BY cohort_month ORDER BY period_number) * 100, 2) AS retention_rate
FROM cohort_index
GROUP BY cohort_month, period_number
ORDER BY cohort_month, period_number;
```

* **Core Finding:** Month 1 repeat purchasing decayed to $< 0.7\%$ across all cohorts, with long-term retention stabilizing near $0.2\%$. 
* **Business Takeaway:** Paid acquisition budgets cannot rely on natural organic repeat purchases. Growth requires either continuous top-of-funnel customer acquisition or structured post-purchase replenishment incentives.

### 2. Quintile RFM Customer Segmentation
Customers were scored across three core behavioral dimensions using quintile distributions ($NTILE(5)$):
* **Recency ($R$):** Days elapsed since the customer's most recent delivered order.
* **Frequency ($F$):** Total count of unique completed transactions.
* **Monetary ($M$):** Total gross merchandise value spent across all orders.

$$R_{\text{score}}, F_{\text{score}}, M_{\text{score}} \in \{1, 2, 3, 4, 5\}$$

```sql
-- RFM Customer Segmentation (DuckDB SQL)
WITH customer_rfm AS (
    SELECT 
        c.customer_unique_id,
        DATEDIFF('day', MAX(o.order_purchase_timestamp), '2018-09-03'::TIMESTAMP) AS recency_days,
        COUNT(DISTINCT o.order_id) AS frequency_count,
        SUM(o.payment_value) AS monetary_value
    FROM fact_orders o
    JOIN dim_customers c ON o.customer_id = c.customer_id
    WHERE o.order_status = 'delivered'
    GROUP BY c.customer_unique_id
),
rfm_scores AS (
    SELECT 
        customer_unique_id,
        recency_days,
        frequency_count,
        monetary_value,
        NTILE(5) OVER (ORDER BY recency_days DESC) AS r_score,
        DENSE_RANK() OVER (ORDER BY frequency_count ASC) AS f_score,
        NTILE(5) OVER (ORDER BY monetary_value ASC) AS m_score
    FROM customer_rfm
)
SELECT 
    customer_unique_id,
    r_score, f_score, m_score,
    CASE 
        WHEN r_score >= 4 AND m_score >= 4 THEN 'Champions & Loyal'
        WHEN r_score <= 2 AND m_score >= 4 THEN 'Dormant Big Spenders'
        WHEN r_score <= 2 AND m_score = 3 THEN 'At-Risk High-Value'
        WHEN r_score >= 4 AND m_score <= 2 THEN 'Recent Low-Value Buyers'
        ELSE 'General Buyer'
    END AS customer_segment,
    monetary_value
FROM rfm_scores;
```

* **Core Finding:** The *Dormant Big Spenders* and *At-Risk High-Value* segments account for **~R$ 4.4M in GMV**, despite representing under half the buyer volume of general one-off purchasers.
* **Business Takeaway:** Automated retention workflows (e.g., targeted email win-back sequences) should focus strictly on these high-monetary cohorts rather than blanket-discounting the entire user base.

### 3. Pareto Catalog Distribution (80/20 Rule)
Product category sales were ranked to quantify marketplace supplier dependency:

$$\text{Cumulative GMV Share}(k) = \frac{\sum_{i=1}^k \text{GMV}_i}{\sum_{i=1}^N \text{GMV}_i}$$

```sql
-- Category Pareto Distribution (DuckDB SQL)
WITH category_revenue AS (
    SELECT 
        p.product_category_name_english AS category,
        ROUND(SUM(oi.price), 2) AS total_gmv
    FROM fact_order_items oi
    JOIN dim_products p ON oi.product_id = p.product_id
    GROUP BY p.product_category_name_english
),
ranked_categories AS (
    SELECT 
        category,
        total_gmv,
        SUM(total_gmv) OVER (ORDER BY total_gmv DESC) AS cumulative_gmv,
        SUM(total_gmv) OVER () AS total_marketplace_gmv
    FROM category_revenue
)
SELECT 
    category,
    total_gmv,
    ROUND((cumulative_gmv / total_marketplace_gmv) * 100, 2) AS cumulative_gmv_pct,
    ROUND((ROW_NUMBER() OVER (ORDER BY total_gmv DESC)::FLOAT / COUNT(*) OVER () * 100), 2) AS category_share_pct
FROM ranked_categories
ORDER BY total_gmv DESC;
```

* **Core Finding:** **80% of marketplace revenue is concentrated in only 23% of categories**, dominated by *Health & Beauty*, *Watches & Gifts*, and *Bed, Bath & Table*.
* **Business Takeaway:** While catalog breadth appears large (70+ categories), the business is vulnerable to supplier churn and stockouts within its top 16 categories.

## Interactive BI Dashboard (Streamlit)

The application provides an interactive analytics cockpit built in Python and Streamlit, querying pre-aggregated Parquet tables via DuckDB:

* **Executive KPI Tiles:** Dynamic metrics for Total GMV, Total Orders, Average Order Value (AOV), and Active Buyers with date-range slider controls.
* **Cohort Heatmap View:** Interactive Seaborn/Plotly matrix displaying retention decay percentages across customer tenure.
* **RFM Scatter & Treemap:** Visual breakdown of revenue concentration across customer behavioral clusters.
* **Pareto Curve Simulator:** Interactive cumulative GMV curve identifying the exact inflection point of 80% revenue share.

## Quickstart & Execution Guide

### 1. Environment Setup
Clone the repository and install the frozen dependencies:

```bash
# Navigate to project directory
cd sales_customer_analytics

# Install dependencies
pip install -r requirements.txt
```

### 2. Execute Data Transformations
Run the DuckDB SQL scripts to process the raw transaction data into Parquet marts:

```bash
python -c "import duckdb; conn = duckdb.connect(); conn.execute(open('sql/01_staging.sql').read())"
```

### 3. Launch the Streamlit Analytics Application
Start the local BI web dashboard:

```bash
streamlit run app/streamlit_app.py
```

The application will launch in your browser at `http://localhost:8501`.
